## Executive summary

The storefront is deliberately minimal (stateless, no DB, one form) and its
tests, i18n parity, CSRF and no-JS fallbacks were already solid. The audit's
central finding was deployment-shaped: the ONE persistence path the product
has — the contact-form log line — was silently filtered out by the shipped
`LOG_LEVEL=warning` on both deploy targets, so every lead evaporated while
the form looked fine. Three smaller deployment/security gaps (proxy trust,
`.env` baking into images, an open redirect) round out the fixes.

## What changed (verified: 20 tests passed / Pint clean)

| Area | Change | Why |
|---|---|---|
| **Lead capture (critical)** | `.env.example` ships `LOG_LEVEL=info` (was `warning`, which filtered `Log::info` at the Monolog handler on Render AND Vercel); a test pins the shipped level ≤ info | the log is the only record of a lead (ADR-013) — every submission was being silently discarded |
| Rate limiting | `trustProxies(at: '*')` | the throttle keyed on the edge IP — the whole site shared one 5/min budget |
| Security headers | `SetSecurityHeaders` middleware: `X-Frame-Options`, `nosniff`, `Referrer-Policy`, HSTS when HTTPS | baseline hardening for a public page |
| Open redirect | `/lang/{locale}` only follows same-app referers; others land on the landing page | `redirect()->back()` trusted the raw Referer header |
| Log resilience | a failed log write is reported and the thank-you flow completes | the log write is persistence; it must not 500 the UX |
| Image hygiene | `.env`, `.env.*`, `package-lock.json` added to `.dockerignore`; stray lockfile deleted | a local `.env` with a real `APP_KEY` was baked into BOTH images and preferred by the FrankenPHP entrypoint |
| Dead files | `docker/entrypoint.vercel.sh` + `docker/apache/vhost.vercel.conf` deleted (they still migrated a SQLite DB and referenced the removed `/__debug` route) | ADR-013 stateless; nothing references them |
| `composer run setup` | no npm install/build, no migrate; dead factory/seeders autoload removed | contradicted "no Node, no database" |
| UX/a11y/i18n | hero copy chip handles Enter/Space (WCAG 2.1.1); contact page has its own meta description (EN/ES); session cookie defaults to `Secure`; entrypoint `APP_KEY set:` diagnostic reports truth | small correctness fixes |
| Docs | pages table gains `/contact/thank-you` + `/lang/{en\|es}`; Design section corrected to "Datum v3" (ADR-015); **`README.es.md` created** — the repo ships bilingual docs everywhere and the README was the last English-only holdout | docs must describe the actual system |

## Remaining recommendations

1. `config/database.php` still carries the full skeleton connection blocks
   (and a config-load-time `/tmp/storefront` probe) for a DB that cannot
   exist here; pruning it to the sqlite-null session/file cache reality
   would remove boot-time filesystem probing. Left in place — it is the
   Laravel skeleton default and changing it buys nothing functional.
2. Search engines only see the default EN pages (locale lives in the
   session; no per-locale URLs). If ES SEO ever matters, add `?lang=es`-style
   URLs + `hreflang` alternates as an explicit follow-up.
3. Vercel cold-starts mint a fresh `APP_KEY` per instance (documented);
   passing `APP_KEY` in the dashboard keeps it stable and avoids in-flight
   419s if the site ever scales beyond one instance.

## Addendum — UI/UX polish pass (2026-09-09, same day)

A rendered-browser UI pass (1440×900 + 390×844, EN/ES) found and fixed three
storefront defects. Full context lives in the Core report:
`B2B-Core/docs/UI-AUDIT-2026-09-09.md`.

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | P1 | Mobile header overflow: the topbar demo CTA plus the "Menú" label pushed the hamburger — and the open dropdown — past the viewport edge on phones | CTA hidden ≤940 px (the menu carries the same CTA); label hidden ≤620 px (icon-only). Desktop unchanged |
| 2 | P2 | 390 px horizontal page scroll: `.widget` pairs `width:100%` with padding under `content-box` (+38 px); `.bento` tracks grew to items' min-content; the hero demo ledger table (nowrap mono) had no scroll container | `box-sizing: border-box` on `.widget`; `.bento > * { min-width: 0 }`; table wrapped in `.ledger-wrap { overflow-x: auto }` |
| 3 | P5 | Package-counts widget bars look inconsistent per row (Cards 200 → short bar) | Investigated: bars scale across tiers within a row (12 % → 100 %), consistent with the published packages and disclosed by the widget note. Left as designed |

Verified after fixing: `scrollWidth == clientWidth` at 390 px on every page;
hero unchanged at 1440 px; empty contact submit still trips native validation.
